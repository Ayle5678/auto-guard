# 0021 — 守卫面共享文案目录：守卫面键归 core，宿主只留 chrome

> Status: ready-for-agent
> 决策依据：ADR-0023；grill-log Round 16 Q4–Q5。修订 CONTEXT「消息目录」词条的「文案归各包所有」旧表述。

## Problem Statement

七个消息目录里，同一守卫面键最多三处定义且中文措辞已语义漂移：删除复核双标题三种措辞（运行时「本次删除」/ pi「这次删除未过审」/ dsh「否决了这次删除」）、回滚回执与学习分析回执各三种拼法、ping/审计/key 类键三目录逐字重复。改一句用户可见的守卫面文案要跨三个包；措辞漂移意味着同一句话在不同宿主已经说法不一。付税的是文案维护者；用户看到的是不一致的措辞。

## Solution

守卫面键（回执、usage、删除流程、密钥与审计、学习分析回执）提升为 core 的共享守卫面目录（defineCatalog 旁）；键迁移按三步审计进行：逐字相同直接搬、同义异形统一为语义最准的正典、承载宿主上下文的措辞走描述符 catalogOverride 数据槽保留。四个宿主侧目录（运行时、pi、dsh、cli）瘦身为宿主 chrome（对话框、设置页、安装器、TUI 文案留在各自包内）。个别同义漂移键的文案统一是本次唯一被接受的用户可见变化——不改变任何判断与操作方式，键级 diff 清单进验收。

## User Stories

1. 作为文案维护者，我希望一句守卫面文案只有一处定义，所以改措辞一次生效、不可能再漂移。
2. 作为多宿主用户，我希望同一个回执在所有宿主说法一致，所以不再看到三种「删除被否决」。
3. 作为贡献者，我希望新增守卫面键只写一次，所以全部宿主与 CLI 同时获得。
4. 作为 pi/dsh 用户，我宿主特有的对话框与设置页文案不变（chrome 归宿主），所以宿主味道不被抹平。
5. 作为双语用户，我的语言设置四层解析行为不变，所以中英切换零影响。
6. 作为审计者，我希望用户可见文本的每一处变化可审计，所以统一措辞以键级 diff 清单验收。
7. 作为新宿主作者，我希望 chrome 目录只剩真正宿主味的键，所以抄目录时抄到的都是必须自己写的。

## Implementation Decisions

- **共享目录位置**：core，defineCatalog 旁——pi 与 dsh 不经宿主运行时，cli 依赖 core；core 是唯一公共下游。
- **三步审计迁移**：(a) 同键逐字相同（多数：ping、审计开关、key 展示、examine 家族）直接搬；(b) 同义异形（删除复核双标题、回滚回执、学习分析回执）选语义最准者统一；(c) 宿主上下文措辞走 catalogOverride（ADR-0016 已建机制，hook 宿主先行、pi/dsh 沿用）。
- **机制不动**：defineCatalog 类型对齐、每包目录纪律、四层语言解析（ADR-0011）全部照旧——动的只是键的家。
- **usage 程序名**：随 SPEC 0020 的程序名参数化，键单源后前缀以参数注入。
- **chrome 边界**：安装器、TUI、pi 对话框、dsh 设置页文案明确留在包内，不进共享目录。

## Testing Decisions

- 既有语言目录测试（键一致性、类型对齐）全绿；双语等价 conformance 断言全绿。
- **键级 diff 清单**作为验收附件：每个统一措辞的键列出迁移前三措辞与迁移后正典，用户可见变化逐条可审。
- 新增守卫面目录的正典快照测试（防未来再漂移）。

## Out of Scope

- chrome 目录的任何合并或搬运。
- defineCatalog 机制、四层语言解析的改动。
- ADR-0025 的策略下沉（vetoTitle 查词走本目录，但策略函数属 SPEC 0022）。
- 措辞正典的内容评审（以「语义最准」为唯一标准，不做文案美化）。
