# 删除分级：目录删除复核内的三级处置门

目录删除复核（SPEC 0019）自诞生起对所有递归删除一刀切：首击拒 + `[删除理由]` 协议 + 单次复审。2026-10 统计（decision-history，30 天窗口）：143 次删除流决策中 80 次首击要理由、11 次理由协议未接上——约三分之二纯协议往返，其中约一半目标是可再生缓存或 agent 自建小临时目录；另一端，workspace 外的根邻近大目录在 LLM 复审 allow 后即放行，无人工关口。决策：删除流入口以 stat 信号分级，三级处置——**严格**（任一目标命中敏感路径 / 根邻近〔盘根或家目录之下 ≤`strictMaxDepth` 级，默认 2〕/ 规模超上限〔≥`largeMinFiles` 默认 1000 或 ≥`largeMinBytes` 默认 500MB〕）：理由协议照走 + high 推理复审 + **结论上限收为 ask**，LLM 无权独自放行；**轻量**（全部目标在 workspace 或系统临时区子树内，且 basename 命中可再生名〔`__pycache__`、`node_modules` 等〕或规模 ≤200 文件且 ≤50MB）：免理由协议、整条命令转一次普通评审，放行只写会话短 TTL 缓存；**标准**（其余）：现行流程原样。目标 stat 全为普通文件时回落普通管线（与 Remove-Item 运行时检测的 file 降级既有语义对齐）；stat 失败保守落标准。全部阈值住 defaults.json 顶层 `directoryDeletePolicy` 数据字段。分级只在删除流内改变处置，**不改** ADR-0012 的分类不变式与优先序——递归删除仍必进目录删除流。

## Considered Options

- 出 workspace 即严格：拒绝——`cd $TEMP && rm -rf piwf` 类小临时目录会被打到最严级（grill 2026-10-05 Round 1）；升严的真实信号是"位置危险"（根邻近）与"规模大"，不是"出了 workspace"这个事实本身。
- 用静态白名单放行可再生缓存（动分类层）：拒绝——违反 ADR-0012 分类优先序冻结的决策；且白名单命中完全跳过评审，轻量级仍保留一次 LLM 评审（评审员看得到这条 rm）。
- 轻量放行写持久缓存（同 unknown 的 30 天免审）：拒绝——目录内容会变，今日 `__pycache__` 的判断不代表下周同名目录还是缓存；仅会话短 TTL（grill Round 2 Q8）。
- 严格级允许 LLM allow 生效：拒绝——该级存在的意义就是"必须过人的手"（用户原话场景：D 盘下放了很多文件的大目录）。
- 规模扫描不封顶：拒绝——node_modules 式目录会拖垮 hook 进程预算；封顶即判定（计数到大规模阈值即停、超限即"大"）天然规避。
- 位置危险用"workspace 外"表达而非根邻近：拒绝——workspace 外的深处小目录（深度 ≥3）与 workspace 内同规模目录爆炸半径相当，按位置类别一刀切会误伤（见第一条）。

## Consequences

- agent 开发循环中最高频的临时/缓存目录删除从"2+ 轮协议往返 + 1 次复审"降为"1 次普通评审"；根邻近/大目录从"LLM 可独自放行"收紧为"必经人工确认"。
- 删除流新增 stat + 封顶扫描成本：上限约 1000 个 dirent 的浅层遍历，毫秒级，hook 预算内。
- `rm -rf <文件>` 不再进理由协议——"目录删除复核"名副其实只管目录；文件删除回归普通评审，敏感路径门照常先拦。
- defaults.json 新顶层字段经 ADR-0013 补齐语义到达存量安装；各机器可调松紧（阈值全可配），用户 rules.json 整体覆盖。
- 已知残余（接受）：`powershell -Command "rd /s /q …"` 这类 cmd 内建词包在 powershell 里的形态，分类层不识别为删除、落 LLM 兜底——比误放行安全。
- 配套修复（同 SPEC 0028）：目标提取剥 powershell/cmd 包装，消除重试邻居匹配提不出目标导致的"理由贴不上"循环。
