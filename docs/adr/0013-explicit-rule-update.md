# 出厂规则升级走 init 显式步骤；运行时永不静默合并

规则文件双层结构下（播种的 defaults.json + 用户 rules.json，加载时用户字段**整体胜出**，`mergeMissingRuleFields` 只补整段缺失的顶层字段），出厂默认新增的模式**到不了存量安装**：`rm -r` 缺口修复时需在本机三宿主（pi/qoder/zcode）手工同步 defaults.json 与 rules.json 共六份文件（2026-08-29）。

决策：**维持这一不可传播语义，不改为运行时自动合并**——它是 ADR-0008「写入显式、幂等、可完全卸载」的一致推论：静默改写用户拥有的规则文件违背显式性，且无墓碑机制防止「用户故意删除的模式复活」。规则升级改为安装器的**显式步骤**：`auto-guard init` 检测到出厂默认含本地缺失的模式时，展示 diff 预览，用户确认后按「幂等追加 + 去重 + 写前 `*.auto-guard.bak` 备份」写入 defaults.json 与 rules.json；拒绝则保持原样。

## Considered Options

- 运行时加载期自动追加新默认模式：魔法行为、需删除语义（墓碑）配套，违背显式写入立场。
- 仅文档声明「重装即可升级」：defaults.json 与 rules.json 均为用户所有、播种函数对已存在文件是 no-op，声明与行为不符。

## Consequences

- 显式更新前，存量安装持续按旧规则运行；本机 pi/qoder/zcode 六份文件的手工补丁即为该流程的首次人工执行。
- 安装器新增一个只追加、去重、可预览、可拒绝的子步骤；`remove` 卸载语义不受影响。
- 播种（首次运行缺字段补齐）语义保持不变；本 ADR 只约束「已有数组内追加新模式」这一情形。
