# 语言设置：四层解析 + 每包消息目录；理由语言跟随设置，协议标记不双语

全产品（安装器、管理 CLI、core 引擎、三个宿主适配层）的用户可见文案支持中英双语。语言设置四层解析：`AUTO_GUARD_LANG` 环境变量（一次性覆盖）> 每宿主 `config.lang`（`set lang` 写入，随配置根持久化）> 机器默认语言（`~/.auto-guard/config.json`，auto-guard 自身命名空间，安装器提问后立即写入）> 中文兜底。中文兜底保证既有管道、CI 与全部存量测试输出逐字节不变。LLM 裁决理由的语言跟随语言设置（提示词按配置追加语言指令）；已存的审计记录与决策历史不翻译。`[删除理由]` 是协议标记，保持中文原样、不加别名。

## Considered Options

- 只靠环境变量：拒绝——每次 export，违背「安装选一次、一直用」。
- 安装器把语言播种进各宿主配置根：拒绝——违反 SPEC 0002「init 不创建 `~/.<host>/auto-guard/`」，破坏 `guard status` 的「未播种」信号。
- 引入 i18n 框架：拒绝——零运行时依赖原则下纯属负担。
- 全部文案集中 core 一个大目录：拒绝——文案归消费者所有，core 只出类型与取词函数（`message`/`Lang`，纯函数+数据，符合 ADR-0002）。
- ask-memory 四选项继续按中文字面匹配：拒绝——那是显示文案与匹配键的耦合，本地化必然踩断；改为结构化值匹配。
- 本地化 `[删除理由]` 标记：拒绝——协议兼容优先。

## Consequences

- 引擎多读一个机器级小 JSON；`set lang` 之后按新语言回执，`guard status` 显示当前生效语言。
- 机器默认变更会影响未显式配置语言的宿主（这正是「机器默认」语义）；已显式 `set lang` 的宿主不受影响。
- `remove` 不清除机器默认（与「数据根保留」同理）；`init --lang` 与交互提问都更新机器默认，单独换语言无需重装。
- 已安装宿主不受 init 重跑影响（marker 幂等）；profile 的 statusMessage 按安装时语言写入，重装才换。
- 新增语言 = 各包目录各加一列，不动流程代码。
